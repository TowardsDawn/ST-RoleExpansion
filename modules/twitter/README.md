# 推特（Twitter）

`modules/twitter/` 的**用户说明**。安装扩展、给酒馆打补丁、模块怎么启用 / 拆卸这些全局步骤见[主 README](../../README.md)；
实现细节见 [DEVELOPMENT.md](DEVELOPMENT.md)。

拆掉整个 `modules/twitter/` 目录（或在酒馆「扩展」设置面板里禁用它）= 没有推特功能；
框架与「日记」「角色状态栏」照常工作（推特不依赖任何其它模块，别的模块也不依赖它）。

---

## 这个模块能做什么

| 能力 | 说明 |
| --- | --- |
| 把回复里的推文收进时间线 | 模型在角色回复里写 `<推文>…</推文>`（可带 `<推文时间>…</推文时间>`），扩展把它剪成一条推文存下来，并把这些标签从正文里剥掉 |
| 仿推特主页 | 面板里画一个推特页面：横幅 / 头像 / 名字（可带蓝勾）/ handle / 简介 / meta 行 / 正在关注与粉丝 / 四个标签页 / 推文列表 |
| 手动维护 | 「新增推文」按钮；每条推文「置顶 / 编辑 / 删除」；置顶只允许一条 |
| 主页上能点 | `关注` ⇄ `正在关注`（顺带粉丝数 ±1）、`🔄 n` ⇄ `🔄 n+1`、`❤️ n` ⇄ `❤️ n+1` —— 数值与颜色都写回 jsonl |
| 推文配图 | 给任意一条推文上传一张图（自己传，模型不管）；没配图的推文就是纯文字样式 |
| 按会话隔离 | 一个会话一个 jsonl（外加两张图片），放在该角色的聊天目录下；换角色、换存档互不干扰 |

数据分三类来源，改法各不相同：

| 来源 | 具体是哪些 | 怎么改 |
| --- | --- | --- |
| **用户编辑** | 名字 / 认证 / handle / 简介 / meta / 正在关注 / 粉丝；头像与横幅图片；**每条推文的配图** | 资料区 / 「新增推文」「编辑」弹窗，改动自动落盘 |
| **模型输出** | 推文正文 + 推文时间 | 由模型按标签契约写在回复里；也可以在面板上手动新增 |
| **随机生成** | 评论 / 转发 / 点赞 / 浏览 | 创建时按规则随机生成一次；之后在 `新增推文` / `编辑` 弹窗里能改，也可以手改 JSONL（见「四个数字」） |

> 另外：主页上的 `关注` / `🔄` / `❤️` 是**可点的交互**，点一下会改上面的「粉丝数 / 转发数 / 点赞数」并按会话落盘 —— 见「点一下会变什么」。

不做的事：群聊不支持（见「群聊与缺补丁」）；**不**写回 ST 的角色头像；不创建 / 不修改聊天记录本身（除了把标签从最后一条回复的正文里剥掉）。

## 入口与面板结构

| 入口 | 位置 |
| --- | --- |
| 顶部工具栏的**羽毛图标** | 主面板里的「**推特**」区块 —— 排在最上面、**横跨整行**、**默认收起**（点标题展开；位置见主 README 的界面导览） |
| 角色卡编辑区 | `Chat Lore` 按钮右侧的羽毛按钮，打开的是同一个主面板 |

「推特」区块自上而下：

1. **仿推特页面** —— iframe 里的那个主页：标签页 `帖子 / 回复 / 媒体 / 喜欢` + 推文列表。
   **固定高度的一屏**：横幅 / 头像 / 名字 / 简介 / 统计 / 标签页这些头**钉住不动**，
   推文列表自己带滚动条 —— 推文再多、配图再高，面板也不会被撑长。
2. **资料区（头像 / 横幅 / 文字）** 折叠块（**默认收起**）—— 见「资料区」。
3. **推文管理** 折叠块（**默认收起**）—— 自上而下：
   - **状态行**：正常时是 `N 条推文 · chats/<角色目录>/_RoleExpansion/twitter/<文件名>.jsonl`；
     不可用时换成**红字原因**（群聊 / 缺补丁 / 路径被拒 / 超限 / 网络错…），此时页面会被隐藏。
     「**还没有选择角色**」不算出错：这一行留空，不打红字。
   - `新增推文`（手动加一条，模型不配合时用）、`刷新`（从文件重读一次 jsonl + 头像 / 横幅 / 每条推文的配图）。
   - 推文列表本身：每条一行，右侧三个按钮 `置顶 / 编辑 / 删除`；
     行内预览 `时间 + 正文前 60 字 + 💬🔄❤️📊`，列表超过 420px 内部滚动。
   - 状态与这两个按钮放在这里（而不是正文顶部）是因为**这块默认收起**：不打开就完全不占高度，
     省下的 ≈82px 全给了 iframe。
4. **解析设置** 折叠块（**默认收起**）—— 两个开关，见「解析设置」。

三个折叠块的标题行比别处薄一档（每个约 4px），也是为了给 iframe 腾高度。

页面里只有「帖子」标签有内容；点「回复 / 媒体 / 喜欢」会显示一句
`「X」标签下还没有内容 —— 本模块只收录纯文本推文。`。
右上角的 `···` / `✉` / `关注` 三个按钮是**装饰**，点了没反应（srcdoc 里没有任何脚本）。

## 模型该怎么写标签（契约）

| 标签 | 必填 | 作用 |
| --- | :---: | --- |
| `<推文>正文</推文>` | ✅ | 一条推文；**一条回复里可以写多组** |
| `<推文时间>2小时前</推文时间>` | ⭕ | 配给**它后面的第一条** `<推文>`；配完即作废 |

✅ 正例（一条回复里两组标签，各带一个时间）：

```text
（她掏出手机看了一眼，然后把屏幕转过来）
<推文时间>2小时前</推文时间>
<推文>今天去看海了🌊
风很大。</推文>
<推文时间>昨天</推文时间><推文>新买的耳返到货了。</推文>
```

✅ 也能不带时间（时间留空就不显示「· 时间」那一段）：

```text
<推文>在便利店看到一只有点像你的猫。</推文>
```

❌ 反例与后果：

| 写法 | 结果 |
| --- | --- |
| `<推文 时间="2小时前">…</推文>` / `【推文】…【/推文】` / 全角 `＜推文＞` | 认不出来，整段当普通正文留在回复里 |
| `<推文>没有闭合` | 认不出来，不收 |
| `<推文></推文>`（正文只有空白） | **不收录**，控制台记一行 `(空推文)` |
| 时间标签写在 `<推文>` **后面** | 不会回溯配给前一条：它要么配给**下一条**推文，要么算孤儿 |
| 连续两个时间标签 | 前一个算孤儿（控制台记 `N 个没配到推文的时间标签`），最后一个待配 |
| 推文正文里写 HTML | 会被转义成文本显示，不会真的变成标签 |
| 只写了 `<推文时间>`、整条回复没有 `<推文>` | **不收、也不动正文**，只在控制台记一行 |

**剥离规则**（由「解析设置」里的剥离开关控制）：

- 只要这条回复里出现了 `<推文>`，就把 `<推文>` 与 `<推文时间>` **两种标签整段剥掉**（含没配到推文的孤儿时间标签），
  并把 3 个以上连续换行压成 2 个、前后 `trim()`；
- 只有孤立的时间标签（整条回复没有 `<推文>`）时**不动正文**；
- 关掉剥离开关 → 标签留在正文里，但**推文照常收录**；
- 剥离是**就地改写**那条消息的正文（不是显示层隐藏），所以聊天记录里也看不到标签了。

解析范围与前提：只看**最后一条**消息（最后一条是用户消息、或正文不是字符串时不动）；群聊不解析；
本插件正在写日记的那次生成不解析；「解析模型回复里的推文」关掉时整个解析（含剥离）都不执行。

## 手动新增与编辑

- 工具行 `新增推文` 打开弹窗：**时间**（可留空）/ **序号**（默认 = 当前最大 + 1）/ **正文** / **四个数字**（预填一份随机值）。
  正文空会提示「正文不能为空。」；保存时提示「已新增一条推文。」。
- 「推文管理」里的 `编辑` 打开同一个弹窗：时间、序号、正文与四个数字都可改，保存即落盘。
- 数字框留空 = 用随机值；写进 JSONL 的永远是整数（`1.6K` 只是显示写法）。
- `删除` 有二次确认（`确定删除这条推文？此操作不可撤销。`）。

序号与时间的分工见下节；**时间只是显示文本**（`2小时前` / `昨天` / `6月1日` 都行，扩展不解析、不比较）。

## 排序与置顶规则

**时间不参与排序**，排序只看序号 `seq`：

1. **置顶**的推文（至多一条）**恒在最上面，且只出现一次**；
2. 其余按 `seq` **从大到小**（新 → 旧）；`seq` 相同时按创建时间新的在前。

关于 `seq`：

- 新增时默认 `seq = 当前最大 + 1`（`nextSeq()`），所以**越大越新、排得越上面**；
- 弹窗里可以手动改（>= 1 的整数，不是数字时按 1 处理）；
- 从模型回复里捕获的推文也走这条路（看不到弹窗，`seq` 自动 +1）。

关于置顶：

- **只有你来点**：管理列表每行的 `置顶` / `取消置顶` 按钮，扩展从不自动置顶；
- 只允许一条：点某条的 `置顶` 会把其它条全部取消置顶；再点一次同一条 = 取消置顶；
- 手改 JSONL 若把两条都写成 `"pinned": true`，页面与列表里也只显示一条置顶。

## 点一下会变什么（关注 / 转发 / 点赞）

仿推特主页上有三个能点的东西，**点完立刻写回 jsonl**（不是只改显示）：

| 点哪里 | 第一次点 | 再点一次 |
| --- | --- | --- |
| 右上角 `关注` | 变成 `正在关注`（去掉白底样式），粉丝数 **+1** | 变回 `关注`，粉丝数 **-1** |
| 推文里的 `🔄 3` | 变成 `🔄 4`，数字变粉（`#f91880`） | 回到 `🔄 3` 与灰色 |
| 推文里的 `❤️ 48` | 变成 `❤️ 49`，数字变粉 | 回到 `❤️ 48` 与灰色 |

- **颜色与数值都存进文件**：推文行多两个布尔字段 `liked` / `retweeted`，资料行多一个 `followed`。
  刷新页面、切会话、甚至手改 JSONL 之后再点，都以文件里的状态为准（`.is-active` 就是「点过」的标记）。
- **写盘失败会自动回滚**：群聊 / 缺补丁 / 路径被拒时点一下，会弹一条错误 Toast，数值与颜色都退回原样 ——
  不会出现「界面变了、文件没变」。
- **点起来是无感的**：这三个交互只改 iframe 里的一个数字与一个颜色类，**不会重建页面**（所以没有刷新与跳变，和样例一样）。
- 面板「推文管理」列表里的数字是同一份数据，点完会一起刷新。
- 三个交互都只**改这份 jsonl**：不碰模型输出、不碰预设、不写回角色卡。

## 推文配图

任意一条推文都可以配一张图（**图是你自己传的**，模型只负责写正文）：

1. 「新增推文」或「编辑」弹窗里找到 **配图** 行；
2. 点 `上传图片` 选一张（会在本地缩到 **1000×1000** 以内：png / webp / gif 保持无损，其它转 JPEG 0.88）；
3. 点 `保存` —— 图片写进 `twitter/tweet-<推文id>.<png|jpg|webp|gif>`，文件名记在这条推文的 `image` 字段里。

| 情况 | 表现 |
| --- | --- |
| 没配图（`image` 为空） | **纯文字推文**，与以前完全一样 |
| 配了图 | 正文下面多一张圆角图（`border-radius: 16px` + 1px 描边，宽度不超出推文） |
| 配图文件被删了 / 读不到 | **什么都不画**（不会出现裂图），控制台记一行「推文配图读不到」 |
| 换图 | 写新文件、**删掉旧文件**（后缀不同也不会残留） |
| `清除配图` | 删掉文件 + 清空 `image` 字段 → 回到纯文字样式 |
| 删除推文 | 它的配图文件一起删掉 |

- 一条推文**只有一张**图；图存在 `twitter/` 子目录里（与头像、横幅同一个目录，都跟着聊天走）。
- 面板「推文管理」列表里，带图的推文正文前面会有一个 `📷` 标记。
- 手改 JSONL 时，`image` 只认 `tweet-` 开头的单段 ASCII 名；写别的（例如路径）会被忽略、不渲染。

## 资料区：头像 / 横幅 / 文字

「资料区（头像 / 横幅 / 文字）」折叠块里：

| 项 | 说明 |
| --- | --- |
| 头像 `上传头像` / `清除` | 上传的图会被缩到 **200×200 PNG** 存成 `twitter/avatar.png`；清除 = 回到空白圆 |
| 横幅 `上传横幅` / `清除` | 上传的图会被缩到 **600×200 JPEG（质量 0.85）** 存成 `twitter/banner.jpg`；清除 = 回到默认渐变底 |
| 名字 | 空时页面显示「（未命名）」 |
| 认证 | 勾选 = 名字后面显示蓝勾（默认开） |
| handle | 例如 `@xxx`；空则不显示这一行 |
| 简介 | 多行文本框，支持换行 |
| meta | **每行一条**（例如 `📍 東京`、`🔗 site.com`）；空行会被丢掉，最多保留 **12** 条 |
| 正在关注 / 粉丝 | **数字输入框**（默认 `0`）；主页上按千分位显示（`3240` → `3,240`），输入里的非数字字符会被丢掉。粉丝数还会被主页上的「关注」按钮 ±1 |

- 文字改动是**边打字边存**（400ms 防抖），图片上传 / 清除立即写盘；
- 上传的图片会**覆盖**固定文件名 `avatar.png` / `banner.jpg`，所以换图不会残留旧文件，也**拿不回原图**（已缩过）；
- `不动 ST 角色头像`：这两张图只存在 `twitter/` 子目录里，和酒馆的角色卡头像无关；
- 手改 JSONL 时，图片文件名取自资料行的 `avatar` / `banner` 字段（默认就是这两个固定名）。

## 四个数字

每条推文有四个数字：**评论 / 转发 / 点赞 / 浏览**。它们在**推文创建的那一刻按下面的规则随机生成一次**：

| 数字 | 规则（闭区间随机整数） |
| --- | --- |
| 浏览 | 500 ~ 50000 |
| 点赞 | 浏览的 2% ~ 8%（至少 1） |
| 转发 | 点赞的 10% ~ 30% |
| 评论 | 点赞的 5% ~ 20% |

四个数是**互相关联**生成的（不会出现「0 浏览却有 5.4K 点赞」这种穿帮）。

**这四个数字随时能改**：`新增推文` / `编辑` 弹窗里各有一个数字框（新增时预填一份随机值，所以不动它也是随机的），
也可以直接手改 JSONL —— 改完点 `刷新`（或刷新页面 / 切会话）就会读回来。

### 存的是整数，`1.6K` 只是显示写法

| JSONL 里存的 | 主页上显示 | 说明 |
| --- | --- | --- |
| `999` | `999` | 1000 以下原样 |
| `1234` | `1.2K` | 1000~9999：一位小数，四舍五入 |
| `1599` | `1.6K` | 同上（1599 / 1000 = 1.599 → 1.6） |
| `1645` | `1.6K` | 同上（1.645 在双精度里略小于 1.645，所以是 1.6 而不是 1.7） |
| `32400` | `32K` | 10000 及以上：取整到 K |
| `1500000` | `1.5M` | 1000000 及以上：一位小数 + `M` |

- 所以**手改 JSONL 时要写数字**（`1234` / `32400`）；写 `1.6K` 会被当成非法值、按 **0** 处理；
- 反过来，界面上的 `1.6K` 是**渲染出来的**，文件里永远是你填的那个整数 —— 不会把约数写回文件；
- 界面里也没有范围校验（只夹到 ≥ 0），生成规则只决定**初值**。

## 存储：落点与手改 JSONL

```text
<user>/chats/<角色目录>/_RoleExpansion/twitter/
├── RoleExpansion_twitter_c_<角色hash8>_j_<会话hash8>.jsonl   文本：会话头 + 资料 + 每行一条推文
├── avatar.png                                                固定名（上传即覆盖）
└── banner.jpg                                                固定名（上传即覆盖）
例：chats/樱井 奈奈/_RoleExpansion/twitter/RoleExpansion_twitter_c_1a2b3c4d_j_5e6f7a8b.jsonl
```

- **为什么跟着角色走**：落点就是角色的聊天目录，角色改名 / 换头像时酒馆会把整个目录搬过去，推特跟着搬；
  删除角色并勾选「删除聊天」时连根删除。酒馆「管理聊天文件」只扫 `chats/<角色>/` **本级**且要求是文件，
  所以子目录里的 jsonl 不会被列出来、也不会被当成聊天加载。
- **文件名是单段 ASCII**（沿用酒馆的文件名校验），所以中文 / 空格 / 括号一律不进文件名：
  角色与会话只进 hash（各 8 位十六进制），可读的角色目录名与会话名记录在文件首行的会话头里。
- **jsonl 是三段结构**（可手改）：

```text
第 1 行  {"__roleExpansion":"twitter-session","version":1,"chatId":…,"charDir":…,"chatFile":…,"savedAt":…,"count":N}
第 2 行  {"__roleExpansion":"twitter-profile", …}   资料区（name / verified / handle / bio / meta / following / followers / followed / avatar / banner）
第 3 行起 每行一条 {"__roleExpansion":"twitter", …}  推文（`image` 是配图文件名，空 = 纯文字）
```

```json
{"__roleExpansion":"twitter","id":"...","time":"2小时前","content":"今天去看海了🌊\n风很大。","seq":1,
 "pinned":false,"liked":false,"retweeted":false,"image":"tweet-abc123.png",
 "stats":{"view":32400,"like":1234,"retweet":210,"reply":60},
 "createdAt":0,"updatedAt":0,"sourceMessageIds":[12]}
```

- 正文里的换行以字面 `\n` 转义保存，保证「一行＝一条」不被破坏；
- **每次落盘都是整文件覆盖写**（会话头 + 资料 + 全部推文），所以手改之后请先 `刷新` 面板再在 UI 里操作，
  免得把磁盘上更新的内容覆盖回去；
- 手改时的容错（读取时会自动整理）：
  字段缺失 / 类型不对会补默认值；`id` 缺失会现场生成；`seq` 不是数字时按「文件里的第几条」兜底；
  四个数字缺失 / 非法一律算 0；`meta` 会去空行、超 12 条截断；
  **不认识的字段会被丢掉**（只保留上面列出的白名单字段）；
- 解析失败的行会被跳过并计数，面板会提示一次「推文文件里有 N 行无法解析，已跳过。」；
- 没有服务端补丁时读写直接失败（原因 `patch-missing`），**不回退**到别的位置。

落盘时机一览：

| 什么时候 | 怎么落 |
| --- | --- |
| 捕获到模型回复里的推文 | 立即整文件写 |
| 资料区打字 | 400ms 防抖后写 |
| 上传 / 清除头像或横幅 | 立即写（先写图片，再写 jsonl） |
| 新增 / 编辑 / 置顶 / 删除推文 | 立即写 |

## 解析设置（两个开关）

「解析设置」折叠块（**默认收起**）里两项：

| 开关 | 默认 | 作用 |
| --- | :---: | --- |
| 解析模型回复里的推文 | 开 | 关掉 → 完全不解析：不收录推文、也不剥标签 |
| 把消费掉的标签从正文里剥离 | 开 | 关掉 → 推文照常收录，但标签留在正文里 |

两个开关都在 `settings` 里（`twitterCapture` / `twitterStripTags`），改完立即生效（不需要刷新页面）。

## 群聊与缺补丁的表现

| 情况 | 表现 |
| --- | --- |
| **群聊** | 状态行红字「群聊不支持：这类文件按角色目录存放，群聊没有角色目录。」；页面隐藏；**本地就判**，连请求都不发；模型回复也不解析 |
| 没有选择角色 | **不当错误显示**：状态行留空、不打红字（这不是本模块出错）；页面隐藏。真要写盘时才会弹「还没有选择角色（角色目录未知）。」 |
| **缺服务端补丁** | 状态行红字点明 `patches/st-twitter-assets.patch`；页面隐藏；**不回退**到别的位置 |
| 服务端拒绝路径（400） | 红字「服务端拒绝了路径（模块名、文件名或角色头像名不合法）。」 |
| 文件超限（413） | 红字「文件超过服务端上限（文本 16MB / 图片 8MB）。」 |
| 网络错 / 其它 HTTP 错 | 红字对应的失败文案（`资源读写失败：http-<code>` 等），由 UI 与 Toast 共用同一份文案 |

不可用时**资料区、推文管理里的输入照旧能打字**，只是写不进去 —— 会弹一条错误 Toast，不静默失败。

## 已知限制

- **只看最后一条消息**：历史消息里的标签不会再被处理；扩展没有「重扫历史」的入口（要补就手动新增或手改 JSONL）。
- **标签写法必须严格一致**：`<推文>` / `</推文>` / `<推文时间>` / `</推文时间>`，不带属性、不成对不收、全角不认。
- **时间只是显示文本**：不解析、不比较、不排序；排序只看 `seq`。
- **一条时间标签只配它后面的第一条推文**，配完即作废；连续写两个时间标签时前面那个会被当成孤儿（控制台记一行）。
- **空 `<推文></推文>` 不收录**；只有孤立时间标签时不动正文，只在控制台记一行。
- **四个数字可以改**（弹窗 / 主页点 🔄❤️ / JSONL），但没有范围校验：负数会被夹到 0，填特别大的数主页上会显示成 `K` / `M` 约数。
- **主页上的 `关注` / `🔄` / `❤️` 会改数据**：粉丝数、转发数、点赞数以及 `followed` / `retweeted` / `liked` 都会写进 jsonl（不是纯展示）。
- **上传图片会被缩小**（头像 200×200 PNG、横幅 600×200 JPEG、推文配图 ≤1000×1000），原图不保留。
- **推文配图一条一张**，文件名固定成 `twitter/tweet-<推文id>.<ext>`：换图会删掉另一个后缀的旧文件，手改 JSONL 时只认这个前缀。
- **不写回 ST 角色头像**；页面里的 `···` / `✉` / `关注` 是纯装饰。
- **「回复 / 媒体 / 喜欢」三个标签页没有内容**：模块只收录纯文本推文，没有类型区分。
- **写盘失败的处理分两种**：编辑 / 置顶只在内存改完直接落盘，失败只有错误 Toast（重读一次即可复原）；
  新增、捕获、删除都会**回滚内存**，其中删除失败会提示「已撤销这次删除」。
- 手改 JSONL 加的自定义字段会在读取时被丢掉（只保留白名单字段）。
- 整文件覆盖写、无写队列：同一会话并发写就是「后写覆盖先写」（正常单人使用无影响）。
- **仿推特页面高度是固定的**（`clamp(520px, calc(100vh - 80px), 1000px)`，见 `style.css` 的
  `.roleEx-twitter-frame`）：它不跟着推文数量长，多出来的内容靠**列表自己的滚动条**看。
  实测可见推文区：808 高的窗口 368px、950 里 486px、1080 里 594px（头固定占 360~406px）。
  （区块自己的固定开销也从 ≈218px 降到 ≈136px，省下的高度一并给了 iframe。）
  **想再大/再小就只改 `style.css` 里那一行** —— 中间那项 `100vh - 80px` 是主项，减得越小列表越高。
- **主面板自己会滚**（这是选择的结果）：页面比面板的可用高度高时，整个面板出现滚动条，滚它时资料头会跟着滚出去；
  只在**列表上**滚鼠标时才是「只滚推文」。要让面板一点不滚，页面高度得压到 `100vh - 405px` 上下
  （808 的窗口只剩 403px，列表几乎为零）—— 两者只能二选一，现在选的是「列表大一点」。
- **资料头是固定的**：简介 / meta 写得很长时，被挤掉的是推文列表的高度（头的行高是固定的，不会自己缩）。
- 界面文案全是硬编码简体中文，没走酒馆的 `t()`。
