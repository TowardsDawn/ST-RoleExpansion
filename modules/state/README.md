# 角色状态栏（`modules/state`）

「角色扩展」里的第二个功能模块：维护一组随剧情变化的数值 —— 生成前告诉模型，生成后从回复里读回来。

> 安装、补丁、模块启用 / 拆卸、面板怎么打开，见主 [README](../../README.md)。本文只讲这个模块。

## 这是什么

主线是一个闭环：

```
你在面板里维护「名称 值」清单，例如 生命值 8/10 / 好感度 42
        │ 发送前注入到主聊天
        ▼
模型知道当前数值 ──→ 在回复里用 <名称>值</名称> 报告变化（<生命值>7/10</生命值>）
        │
        ▼
扩展解析标签 → 更新数值 → 把标签从正文里剥掉 → 下次生成注入新数值
```

- **状态项**：一条「名称 + 值」，例如 `生命值 8/10`、`好感度 42`。值就是任意文本，扩展不解析数值、不做大于小于判断。
- **模型的回报格式**：`<名称>值</名称>`，成对、名称逐字符一致（`<生命值>8/10</生命值>`）。
- **模型不回报就没有更新** —— 没有别的数据来源。

## 面板入口

| 入口 | 怎么到 |
| --- | --- |
| 顶部工具栏羽毛图标 | 在「世界书 World Info」与「用户设置 User Settings」之间；展开的主面板里就是「**角色状态栏**」区块（**默认展开**） |
| 角色管理面板 | 角色卡编辑区 `Chat Lore` 按钮右侧的羽毛按钮，打开的是同一个面板 |

区块内部从上到下：五个开关 → 「状态列表（随会话保存）」+ 清空 / 复制 / 导入 → 「批量添加」文本框 → 默认收起的子区块「**状态注入提示词**」。

## 面板上的开关

| 开关 | 默认 | 做什么 |
| --- | :---: | --- |
| 启用角色状态栏 | 开 | 总开关。关闭后**停止注入，也不再解析标签**（正文里的标签会原样留着） |
| 发送前注入状态提示 | 开 | 只控制注入。关闭后不再注入，标签解析照常 |
| 从聊天消息中剥离状态标签 | 开 | 关闭后标签仍用于更新数值，但会留在正文里 |
| 状态并入日记生成提示 | 开 | 生成日记时把当前状态作为参考（见「与日记模块的关系」） |
| 只接受已知状态名（推荐） | 开 | 模型只更新列表里已有的项；关闭后，回复里的新 `<名称>值</名称>` 会自动加进列表 |

「启用」「发送前注入」两个开关改动后会立刻重算注入；另外三个不影响注入内容。

## 状态列表怎么用

| 操作 | 具体行为 |
| --- | --- |
| 批量添加 / 更新 | 文本框里**每行一条** `名称 值`（第一段是名称，其余全部拼成值）。同名项更新值，新名称追加到列表**末尾**；不足两段的行跳过；一条都没解析出来时提示「没有解析到有效行（格式：状态名 值）。」。成功提示「已更新 N 个状态项。」 |
| 编辑单项 | 点「编辑」→ 名称 / 值变成输入框 → 「保存」写回。名称空提示「名称不能为空。」；与其它项重名提示「已有同名状态项。」；「取消」放弃改动 |
| 删除单项 | 点「删除」，**立即生效，没有二次确认** |
| 清空全部 | 有二次确认（`确定清空当前会话的全部状态项？`）；列表本来就空时点了不做事 |
| 复制为文本 | 输出 `角色状态：` + 每行 `名称 值`，写进剪贴板；没有状态项时提示；剪贴板不可用时退回弹框手动复制（方便粘到世界书） |
| 从文本导入 | 读剪贴板内容塞进文本框，**仍需自己点「添加 / 更新」** |

列表显示：名称一栏固定宽度（够约 10 个汉字，超出省略号），值占剩余宽度；列表最高 420px，再多就内部滚动。

## 「与 chatMetadata 同步」是什么意思

| | |
| --- | --- |
| 存在哪 | 当前会话的聊天元数据 `chatMetadata.roleExpansion.state`（数组，元素是 `{ name, value }`），由酒馆核心负责落盘 |
| 隔离粒度 | **按会话**：换角色、换存档各是各的；**新开一个聊天时状态是空的** |
| 会写回角色卡吗 | **不会**。状态跟着聊天记录走，不是角色设定 |
| 什么时候写 | 面板上的批量添加 / 编辑保存 / 删除 / 清空**立即写**；解析标签带来的更新走 300ms 防抖 |
| 顺序 | 就是列表顺序（新项追加在末尾），注入与 `{{stateList}}` 都按这个顺序输出 |

「清空全部」只清当前会话，且**不可撤销**。

## 标签准入规则

正则先做形状约束：**名称与值里都不能出现 `<` / `>`**，且必须是同名闭合标签。通过之后才有下面这套判据 ——

| 顺序 | 判据 | 说明 |
| :---: | --- | --- |
| ① | 名称已在状态列表里 | **一律放行**，不受下面任何限制：你自定义的 13 个汉字的状态名照样能更新 |
| ② | 名称长度 ≤ 12 | 按**码点**算（常用汉字算 1，emoji 与扩展区汉字也算 1） |
| ③ | 名称不含空白与 `-` `.` `/` `\` | 挡掉 HTML 属性残留、路径样式之类 |
| ④ | 名称不在黑名单里 | 比较前统一转小写。黑名单见下 |
| ⑤ | 到这里说明是**未知名称** | 由「只接受已知状态名」决定：开（默认）→ 拒收；关 → 收录成新状态项 |

黑名单（`NON_STATE_TAGS`）分三类：

```text
HTML     html head body div span style script p br b i u em strong s table thead tbody tr td th
         ul ol li a img hr pre code blockquote h1 h2 h3 h4 h5 h6 font small big center
         iframe video audio source details
思维链   thinking think reasoning analysis thought thoughts reflection plan planning scratchpad cot
工具调用 tool tool_call tool_calls function functions
```

两条容易踩的行为：

- **未通过准入的标签不会从正文里删掉** —— 只有通过准入的标签才会被剥离，被拒的连标签带内容原样留着（旧版本一刀切删除，会误吞 `<thinking>…</thinking>` 和 HTML）。
- 被忽略的标签名会打到控制台：`[ST-RoleExpansion] 忽略了 N 个非状态标签：[…]`，方便确认模型到底输出了什么。

## 解析时机

- 每次收到角色回复（`MESSAGE_RECEIVED`）解析一次，而且**只看最后一条消息**；最后一条是用户消息、或 `mes` 不是字符串时不动。
- 剥离开启时，是把那条消息的 `mes` **就地改写成去掉标签后的文本**（不是显示层隐藏）。剥离前后会把 3 个以上连续换行压成 2 个，并 `trim()`。
- 一个名字在一段正文里出现多次：逐个匹配，后一次的值覆盖前一次。

## 状态注入提示词

「状态注入提示词」是区块内一个**默认收起**的子区块：模板文本框 → 一行「注入深度 / 注入角色」。

**默认模板**（可自由修改）：

```text
当前状态：
{{stateList}}

请参考以上状态。在回答时，如有任何状态数值因剧情发生变化，请仅输出发生变化的状态项，并使用 XML 标签格式表示，例如：<生命值>8/10</生命值>。如果没有状态变化，请不要输出任何状态标签。
```

| 项 | 说明 |
| --- | --- |
| `{{stateList}}` | 替换成每行 `名称 值` 的多行文本；此时必定非空（列表为空时根本不注入） |
| `{{char}}` / `{{user}}` 等 | 剩余宏交给酒馆宏系统替换 |
| 注入位置 | 固定为**主聊天（in-chat）**，不可调 |
| 注入深度 | 默认 `0`，面板上是 0~100 的数字框 |
| 注入角色 | 默认 `system`，可选 `system` / `user` / `assistant` |
| 保存时机 | 边打字边存（防抖 400ms）；深度 / 角色改动后立即重算注入 |

**什么时候真的注入**：三个条件同时满足才注入 —— 总开关开、注入开关开、状态列表非空。否则会**清空注入槽**，不会残留上一次的状态内容。

> 这个子区块**没有**单项「恢复默认」按钮（与日记主提示词一致）：要还原就用酒馆「扩展」设置面板里的「恢复默认设置」，它按你保存的基准整体还原。

## 与日记模块的关系

日记主提示词里的 `{{stateList}}` 由本模块提供（就是上面那段 `名称 值` 多行文本），受面板上「状态并入日记生成提示」开关控制；细节见日记模块文档。

## 已知限制

- **模型不按格式输出就不会更新**。提示词里已经给了格式示例；长期无效就把「状态注入提示词」里的要求写得更硬。
- 默认只收**已知**状态名：模型在剧情里发明的新名称会被忽略（并原样留在正文里）。想收就关掉那个开关，或先手动建一条同名状态。
- 标签必须成对且名称逐字符一致；名称 / 值里不能出现 `<` / `>`，否则整条不匹配。
- 状态存在会话元数据里，**不会写回角色卡**；新开聊天状态为空。
- 旧数据 `chatMetadata.sillyTavernState` 在扩展这侧为空时**只自动迁入一次**（原键保留不删）；之后点「清空全部」也不会让它复活。
- 「清空全部」与单项「删除」都不可撤销（只有清空有二次确认）。
- 关掉「从聊天消息中剥离状态标签」只是让标签留在正文里，数值照常更新。
