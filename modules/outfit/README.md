# 衣装打扮（Outfit）

`modules/outfit/` 的**用户说明**。安装扩展、给酒馆打补丁、模块怎么启用 / 拆卸这些全局步骤见[主 README](../../README.md)；
实现细节见 [DEVELOPMENT.md](DEVELOPMENT.md)。

拆掉整个 `modules/outfit/` 目录（或在酒馆「扩展」设置面板里禁用它）= 没有衣装功能；
框架与「角色状态栏」「日记」「推特」照常工作（衣装不依赖任何其它模块，别的模块也不依赖它）。

---

## 这个模块能做什么

| 能力 | 说明 |
| --- | --- |
| 分类表 | 七个**固定分类**（外：头饰 / 上衣 / 下装 / 袜子 / 鞋子；内：内衣 / 内裤）+ 你自己建的**自定义分类**（固定落在「其他」） |
| 备选装备表 | 每个分类一份备选表（在分类的编辑弹窗里改），按**英文逗号**分隔填若干件 |
| 选择（可叠穿） | 点芯片切换选中，**分类内多选**；顺序恒按备选表顺序，与点击先后无关 |
| **套装**（外 / 内） | 把「固定分类的一整套搭配」存成一个命名套装（例如「通勤装」），**同组互斥单选**；和散装选择**不互斥**，两者会一起注入 |
| 注入主聊天 | 把「现在穿什么」按 **外 / 内 / 其他** 三行分组写进后续每一次生成，让模型的描写与对话保持一致 |
| 按会话隔离 | 一个会话一个 jsonl（备选表、已选、套装都在这个文件里），放在该角色的聊天目录下；换角色、换存档互不干扰 |
| 手改 JSONL | 稳定四行、字段可读；读取时会自动归一化（见「存储」） |

不做的事：群聊不支持（见「群聊 / 没选角色 / 缺补丁」）；**只有单向注入** —— 模型不会自己换衣服、
也没有标签回写（这一点与「角色状态栏」相反，别混）；没有导入 / 导出；不创建 / 不修改 / 不写预设（卡片要你自己加）。

## 入口与面板结构

| 入口 | 位置 |
| --- | --- |
| 顶部工具栏的**羽毛图标** | 主面板里的「**衣装打扮**」区块 —— 排在**最上面**、**横跨整行**、**默认收起**（点标题展开；位置见主 README 的界面导览） |
| 角色卡编辑区 | `Chat Lore` 按钮右侧的羽毛按钮，打开的是同一个主面板 |

「衣装打扮」区块自上而下（正文的**直接子节点顺序是契约**）：

1. **状态行**（`#roleEx-outfit-status`）—— 正常时是 `已选 N 项 · chats/<角色目录>/_RoleExpansion/outfit/<文件名>`，
   一项都没选时是 `还没有选任何衣装项 · <同一个路径>`；有坏行时再跟一句 `· 已跳过 N 行无法解析的衣装数据`；
   不可用时换成**原因文案**（见「群聊 / 没选角色 / 缺补丁」）。
2. **左右两栏**（`.roleEx-outfit-cols`）——
   - 左：**预览**（`#roleEx-outfit-preview`，占 **55%** 宽，并有 `min-height: 12em` 的下限）——
     按 外 / 内 / 其他 分组，一行一个分类，值就是当前选中的 tag（用 `、` 连接）；没选显示「未选」并弱化；
     **外 / 内的第一行是套装行**（`套装：<已选套装名>`，没选显示「未选」）；「其他」组没有套装行。
     分组标题是带 `.roleEx-outfit-preview-part` 的那一行。**预览不折叠**：三组收起后它就是这块面板的主要内容。
   - 右：**编辑器**（`#roleEx-outfit-editor`）—— **三个折叠块**：`#roleEx-outfit-fold-outer`（外）、
     `#roleEx-outfit-fold-inner`（内）、`#roleEx-outfit-fold-other`（其他），**默认全部收起**；
     你展开过的那一组**会被记住**（面板重画 / 切会话回来仍是展开的）。
     每个折叠块里，每个分类**只有一行两个元素**：`分类名`（定宽 13em，超长省略号）+ 靠行最右的 `编辑` 按键
     （`menu_button roleEx-btn-xs`，`#roleEx-outfit-edit-<分类key>`）。
     **外 / 内两组的第一行是「套装」行**（`#roleEx-outfit-cat-suit-<部分key>`，形态与分类行一致，
     只是名字固定是 `套装`、`编辑` 打开的是套装弹窗）。
     「其他」组底部是 `+ 新建分类`（`#roleEx-outfit-add-cat`）。
   - 窄屏（≤780px）下两栏变竖排。
3. **「注入模板」折叠块**（`#roleEx-outfit-inject-fold`，**默认收起**）—— 一个四行文本框，写注入正文的模板。

**点分类行上的 `编辑` → 打开该分类的弹窗**（标题是 `编辑「<分类名>」`）（结构照推特 / 日记的编辑弹窗；同一时刻只会有一个）：

| 弹窗里的元素 | 说明 |
| --- | --- |
| 标题 `编辑「<分类名>」` + 右上角 `×` | 标题只显示当前名字（改名成功后要重开弹窗才看到新名）；`×` = 取消（关窗、不写盘） |
| **名称**输入框（`#roleEx-outfit-modal-name`） | **只有自定义分类才有**（固定分类不可改名） |
| **备选**文本域（`#roleEx-outfit-modal-tags`，3 行） | 这个分类的备选装备表，规则见下一节 |
| 芯片行（`#roleEx-outfit-modal-chips`） | 备选表里每个 tag 一个芯片，**点一下立即切换选中并落盘** |
| 底部按钮（右下角，`.roleEx-row.roleEx-gap.roleEx-end`） | 从左到右：`删除分类`（`#roleEx-outfit-modal-del`，**只有自定义分类才有**、带 `roleEx-danger` 红字）→ `取消`（`#roleEx-outfit-modal-cancel`）→ `保存`（`#roleEx-outfit-modal-save`） |

- **保存的语义**：先存**名称**（改名；只有自定义分类、且只有你真的改过才写盘），再存**备选表**（整表替换；
  同样只有文本变了才写盘）；**两步都成功了才关窗并重画面板**。任一步失败都**停在弹窗里**等你去改：
  名称空 → 提示 `名称不能为空`，名称撞车 → 提示 `已有同名分类`（这两种都**不写盘**），
  写盘失败 → 由 store 弹错误 Toast（内存回滚）。
  ⚠️ 顺序是「先改名、后备选」，所以万一改名成功而备选那步失败，**名字的改动已经生效**
  （窗口标题仍是旧名，等面板重画后显示新名）。
- **取消的语义**：**直接关窗** —— 名称框与备选表框里没保存的文本丢掉、不写盘。
  **但芯片不算**：点芯片本身就是一次即时写入，所以「取消」**不会**撤销刚点过的选择 —— 要撤就再点一次该芯片。
- **备选表为空时弹窗里没有芯片行**，只有一句提示 `先在上面填备选 tag`（没有 tag 就没有可点的东西）。

## 三大部分与分类

| 部分 | 固定分类（key 是契约的一部分） |
| --- | --- |
| **外**（`outer`） | 头饰 `hat` / 上衣 `top` / 下装 `bottom` / 袜子 `socks` / 鞋子 `shoes` |
| **内**（`inner`） | 内衣 `underwear` / 内裤 `underpants` |
| **其他**（`other`） | 你自己建的分类，key 是 `custom-<uid>` |

- 七个固定分类**不可改名、不可删除**（key 同时是注入正文与自测的契约）；JSONL 里缺了就按内置定义补齐。
  它们在弹窗里只有「备选」一行 —— 没有名称框、也没有 `删除分类`。
- 自定义分类：点「其他」组底部的 `+ 新建分类` → 弹一个输入框 → 名字为空、或与任何已有分类重名会被拒绝；
  新建的分类**一定落在「其他」组**（不能挑部分）。它的改名与删除都在该分类的编辑弹窗里做。
- `删除分类` 有二次确认（`删除分类「X」？该分类的备选 tag 与已选 tag 会一起清掉。`），成功才关窗重画。

> 部分顺序（外 → 内 → 其他）**同时决定**编辑器里的分组顺序、预览里的分组顺序、以及注入正文的分行顺序。

## 备选装备表（在编辑弹窗里改）

- 入口：分类行上的 `编辑` 按钮 → 弹窗里的**备选**文本域（`#roleEx-outfit-modal-tags`）。
- **只按英文逗号 `,` 切分** —— 与 SillyTavern 世界书的「关键字列表」一致。
  **中文逗号 `，` 与顿号 `、` 都不是分隔符**，写进去只会变成 tag 名字的一部分。
- 每个 tag 的清洗顺序是：**按 `,` 切分 → `trim()` → 丢掉空串 → 去重保序**。
- 落盘时机：点弹窗里的 `保存`（**不是离开焦点就提交**）。文本与原来一字不差时这一步会被跳过，不产生写盘；
  写盘失败由 store 统一弹 Toast 并把内存回滚，窗口不关。
- 提交是**整表替换**：文本域里的内容就是新的备选表（落盘时写成 `tag1,tag2`，不带空格）。
- **连带清选**：新备选表里已经不存在的 tag，会同时从「已选」里清掉 —— 与读取归一化是同一套语义，
  所以「删掉一个 tag 再打回来」不会自动恢复选中。
- 芯片行按「**弹窗打开那一刻**的备选表」生成：**点一下立即切换选中并落盘**（成功才变样式）；
  改完备选表要先点 `保存`、再重开弹窗，芯片行才会按新表重建。

## 选择语义

| 问题 | 答案 |
| --- | --- |
| 一个分类能选几个？ | **不限个，分类内多选** —— 想叠穿就都点上 |
| 在哪里点？ | 分类行 `编辑` → 弹窗里的芯片行；**点一下立即落盘**（不用点 `保存`） |
| 顺序按什么？ | **恒按备选表的顺序**，与点击先后无关（JSONL 里也只存「选了哪些」，不存顺序） |
| 怎么取消？ | 再点一次该芯片（同样立即落盘）—— 注意「取消」按钮**不会**撤销芯片 |
| 选中长什么样？ | **字色与边框变黄、背景不变**（`border-color: currentColor`） |
| 弹窗里的 `保存` 管什么？ | 只管**名称**与**备选表**；芯片是即时写入，与它无关 |
| 注入时怎么显示？ | 同一个分类里的多个 tag 用 `、` 连接（见下节） |

## 套装（只有 外 / 内 两组）

「套装」= 一组**固定分类**的整套搭配（例如「通勤装」= 头饰 + 上衣 + 下装 + 袜子 + 鞋子各若干件）。
把它存下来，之后点一下芯片就能整组换上/脱下。**「其他」组是自定义分类，没有套装。**

### 怎么建、怎么改

1. 展开「外」或「内」折叠块 → 该组的**第一行**就是 `套装` 行（`#roleEx-outfit-cat-suit-outer` / `-inner`）；
   点它的 `编辑` 打开**一级弹窗** `#roleEx-outfit-suit-modal`（标题 `套装（外）` / `套装（内）`）。
2. 一级弹窗里列出这一组的**所有套装**，每行
   （`.roleEx-outfit-suit-row#roleEx-outfit-suit-row-<套装id>`）从左到右是：
   **套装名** + `编辑`（`#roleEx-outfit-suit-edit-<套装id>`，打开二级弹窗）+ **一颗芯片**（文本就是套装名，点它选中 / 取消）。
   一条套装都没有时那里是一句 `还没有套装，点下面的「+ 新建套装」加一个。`。
3. 底部右下角是 `+ 新建套装`（`#roleEx-outfit-suit-add`）—— 点它弹一个输入框让你填名字；
   留空 = 取消，与同组已有套装重名 → 提示 `已有同名套装`（不写盘）。
4. 点某一行的 `编辑` → **二级弹窗** `#roleEx-outfit-suit-edit-modal`（**叠在一级弹窗之上，一级不关**）：
   - **套装名**（`#roleEx-outfit-suit-name`）；
   - 按固定顺序排的下属分类输入框 —— 外组 5 格（头饰 / 上衣 / 下装 / 袜子 / 鞋子）、内组 2 格（内衣 / 内裤），
     id 是 `#roleEx-outfit-suit-item-<分类key>`；每格填**英文逗号分隔的 tag 串**（与备选表同一套切分规则）；
   - 底部右下角：`删除套装`（`#roleEx-outfit-suit-del`，带 `roleEx-danger`）→ `取消`（`#roleEx-outfit-suit-cancel`）→ `保存`（`#roleEx-outfit-suit-save`）。
5. **保存的语义**：名字为空 → 提示 `套装名不能为空`；与**同组**其它套装重名 → 提示 `已有同名套装`（两种都**不写盘、不关窗**）；
   否则先改名（真的变了才写盘）、再**一次性提交全部下属分类**，全部成功才关窗，并刷新一级列表与面板。
6. **`删除套装`** 有二次确认（`删除套装「<套装名>」？`）；删掉的正好是该组当前选中的那套时，该组的已选会被清空。

### 怎么选

| 问题 | 答案 |
| --- | --- |
| 在哪儿点？ | 一级弹窗里每一行右边那颗**芯片**（文本就是套装名），点一下立即落盘 |
| 同组能选几套？ | **只能一套**（同组互斥）：点另一套会直接换过去 |
| 怎么取消？ | 再点一次**当前已选**的那颗芯片（或点别的套装换过去）；芯片选中态与散装一样是**字色与边框变黄、背景不变** |
| 跨组呢？ | 外和内各自独立，**可以同时各选一套** |
| 和散装选择冲突吗？ | **不冲突**：散装是「分类里额外点上的 tag」，套装是「整组的搭配」，两者会**一起**出现在预览与注入正文里 |

### 预览与注入长什么样

- **预览**：外 / 内两组各自的第一行是 `套装：<已选套装名>`（没选显示「未选」并弱化）；
  下面每个分类行的值 = **散装的选中项在前 + 套装在这个分类里的元素在后、整体去重**，用 `、` 连接 ——
  这就是「装了套装时，各分类位置照常显示该套装包含的元素」。
- **注入正文**：该组真的选了套装时，行首多一段 `套装=<套装名>`（没选就整段不出现），各分类值同预览的合并规则
  （同一分隔符：分类里多个 tag 用 `、`，分类之间用 `；`）。
  例（外组选了「通勤装」，头饰另外散装点了贝雷帽）：

  ```text
  外：套装=通勤装；头饰=贝雷帽；上衣=大衣、白衬衫；鞋子=帆布鞋
  ```

- 空的部分整行不出现；一个衣装项都没有时**整条不注入**（与散装同一条规则）。

## 注入主聊天

### 预设里必须由你自己加一张 marker 卡片

衣装注入走酒馆原生的**有序提示词**机制：预设里放一张 `marker: true` 卡片（`identifier` = `roleExpansionOutfit`），
正文由扩展在每次生成时**现算**提供。卡片片段（写进预设 JSON）：

```jsonc
// 1) prompts 数组里追加一条
{
    "identifier": "roleExpansionOutfit",
    "name": "衣装（角色扩展）",
    "system_prompt": true,
    "marker": true
}
```

```jsonc
// 2) prompt_order 里【每个 character_id 块】都要加一条
{ "identifier": "roleExpansionOutfit", "enabled": true }
```

- 卡片**在不在、落在哪个 `prompt_order` 块、开还是关**，全都在酒馆预设 UI（「AI Response Configuration」）里管；
  扩展**不创建、不修改、不移动**卡片，也不写预设文件。没加卡片时，面板的诊断文案会把上面这段 JSON 直接贴给你。
- **卡片上的开关是「是否注入主聊天」的唯一开关**：关掉 → 运行时正文源返回空串 → 不注入；扩展**绝不**擅自改回来。
- 打开预设面板的快捷入口：「扩展」设置面板 →「衣装卡片 · `roleExpansionOutfit`」那一块里的 `打开预设面板` 按钮。
- **扩展设置面板**里属于本模块的那一块叫「衣装卡片 · `roleExpansionOutfit`」，给的是**诊断**（没有任何可改项）：
  当前预设名、卡片形态（`marker=true`）、所在 `prompt_order` 块与前后邻居、`enabled`，以及权限 / 补丁检测的结论。

### 注入正文长什么样

模板在面板的「注入模板」折叠块里（设置键 `outfitInjectPrompt`，默认两行）：

```text
[以下是 {{char}} 当前的衣装打扮，请在描写与对话中保持一致]
{{outfitList}}
```

- `{{outfitList}}` 是**扩展填的**（store 拼好的分组清单）；其余 `{{...}}` 交给酒馆的宏替换（`{{char}}` / `{{user}}`…）。
- 分组清单：**每部分一行**，该组选了套装时行首是 `套装=<套装名>`，随后是各 `分类名=tag1、tag2`，
  同一行里多个分类用 `；` 连接；**空的部分整行不出现**。
  例（外组选了「通勤装」，头饰另外散装点了贝雷帽；内、其他都没内容）：

  ```text
  外：套装=通勤装；头饰=贝雷帽；上衣=大衣、白衬衫；鞋子=帆布鞋
  ```

- 分类里的值 = 散装选中项在前、套装项在后、整体去重（见「套装」一节）。

- **一个 tag 都没选 → 整条不注入**（不是「注入一行空标题」）。
- 模板框的改动是 400ms 防抖后落设置，立刻生效（不需要刷新页面）。

### 三道正文闸

正文源每次被调用时按顺序判三件事，任一不过就返回空串（= 不注入）：

| # | 条件 | 结果 |
| :---: | --- | --- |
| ① | 卡片**没插进任何** `prompt_order` 块 | 空串（此时连开关都没有，诊断显示 `位置：没有插进任何 prompt_order 块 —— 卡片不会参与生成`） |
| ② | 卡片 `enabled === false` | 空串（诊断显示 `🔴 已停用（不注入）`） |
| ③ | **一个衣装项都没选** | 空串 |

### 可选：把同一份正文喂给世界书扫描（`outfitWIScan`，默认关）

「注入模板」折叠块里还有一行开关 **`纳入世界书扫描`**（设置键 `outfitWIScan`，**默认关**）：

- **扫描文本与卡片正文同源**：扩展把**同一份**正文源又登记了一遍给世界书扫描，
  所以「衣装里的词能不能触发世界书条目」用的就是你在这里看到的那份正文；
  **三道正文闸一并继承** —— 卡片没插进 `prompt_order` / 卡片被关掉 / 一个衣装项都没选时，扫描文本同样是空串。
- **需要 ST 侧的 `st-wi-scan-source` 补丁**（`getContext().registerWorldInfoScanSource`）。
  补丁没生效时这个复选框**禁用**，hint 明说「ST 补丁 st-wi-scan-source 未生效，此项不可用」——**不静默**。
- **为什么默认关**：世界书扫描那一层 haystack **不受 scan depth 截断、在所有扫描轮次（含递归轮）都可见**，
  比「注入主聊天」的影响面大得多 —— 开了之后衣装里的词（「白衬衫」「短靴」这类）可能触发本来不该触发的世界书条目。
- **两个开关各管各的**：卡片上的开关管**注入主聊天**，这一行只管**参与世界书扫描**。
  关掉它，衣装卡片照常注入；关掉卡片，扫描文本也跟着变成空串（因为扫描源读的就是那份正文）。
- 补丁缺失时不会报错、也不会重试：扫描源登记不上只是可降级（衣装不参与世界书扫描），面板上会明说这一项不可用。

## 存储：落点与手改 JSONL

```text
<user>/chats/<角色目录>/_RoleExpansion/outfit/
└── RoleExpansion_outfit_c_<角色hash8>_j_<会话hash8>.jsonl   四行：会话头 + 分类表 + 已选 tag + 套装
例：chats/樱井 奈奈/_RoleExpansion/outfit/RoleExpansion_outfit_c_1a2b3c4d_j_5e6f7a8b.jsonl
```

- **为什么跟着角色走**：落点就是角色的聊天目录，角色改名 / 换头像时酒馆会把整个目录搬过去，衣装跟着搬；
  删除角色并勾选「删除聊天」时连根删除。
- **换会话换文件**（文件名里的两个 hash 分别来自角色目录名与会话名），所以同一个角色的两个存档各穿各的。
- **酒馆看不见它**：酒馆列出聊天文件的所有代码路径都只扫 `chats/<角色>/` **本级**且要求是文件，
  所以子目录里的 jsonl 不会被列出来、也不会被当成聊天加载。
- **文件名必须是单段 ASCII**（沿用酒馆的文件名校验）：中文 / 空格 / 括号一律不进文件名，
  可读的角色目录名与会话名记录在**第一行的会话头**里。
- 读写走服务端补丁提供的 `POST /api/role-expansion/asset/{get,save,delete}`（`sub` = `outfit`，
  服务端子目录白名单里必须有它，见主 README 的「打补丁」）。缺补丁时明确报错（`patch-missing`），**不回退**到别的位置。

### 四行结构

```text
第 1 行  {"__roleExpansion":"outfit-session","version":1,"chatId":…,"charDir":…,"chatFile":…,"savedAt":…}
第 2 行  {"__roleExpansion":"outfit-catalog","categories":[{"key":…,"part":…,"name":…,"custom":…,"tags":[…]}],"updatedAt":…}
第 3 行  {"__roleExpansion":"outfit-selection","picked":{"hat":["贝雷帽","发带"]},"updatedAt":…}
第 4 行  {"__roleExpansion":"outfit-suits","suits":{"outer":[…],"inner":[…]},"picked":{"outer":"","inner":""},"updatedAt":…}
```

```json
{"__roleExpansion":"outfit-catalog","categories":[{"key":"hat","part":"outer","name":"头饰","custom":false,"tags":["贝雷帽","发带"]},{"key":"custom-1a2b3c","part":"other","name":"配饰","custom":true,"tags":["耳坠"]}],"updatedAt":0}
```

```json
{"__roleExpansion":"outfit-suits","suits":{"outer":[{"id":"1a2b3c4d","name":"通勤装","items":{"hat":["贝雷帽"],"top":["大衣","白衬衫"],"bottom":[],"socks":[],"shoes":["帆布鞋"]}}],"inner":[]},"picked":{"outer":"1a2b3c4d","inner":""},"updatedAt":0}
```

- **前三行与 0.10.x 完全一样**（会话头 / 分类表 / 已选），**第 4 行是 0.11.0 新增的套装**：
  `suits` 是外 / 内两组的套装数组（每套 = `id` + `name` + `items`），`picked` 是「这一组选了哪一套」（没选 = `""`）。
- **老文件没有第 4 行 = 空套装表**，不是错误、也不会被计成坏行；反之用**旧版插件**读新文件时，
  旧代码不认识这一行，会在状态行看到一句「已跳过 1 行无法解析的衣装数据」—— 无害（降级场景可忽略）。
- **第 2 行是备选表**（编辑弹窗里的那个文本域）、**第 3 行是已选**（预览与注入正文只看这一份）、
  **第 4 行是套装**。都在**同一个**文件里 —— 手改可行，但落盘是**整文件覆盖写、没有写队列**。
- 写回时永远是「会话头 + 分类表 + 选择表 + 套装表」**稳定的四行**，字段与顺序固定。
- **读不动就丢掉**：固定分类按内置定义补齐；`part` 不在已知部分里的自定义分类丢掉；
  既不是内置分类、又不带 `custom-` 前缀的 key 丢掉；`picked` 里不在分类表里的 key、
  以及不在该分类备选表里的 tag 都丢掉。
- **套装那条的归一化**：`part` 只有 `outer` / `inner` 认，别的一律整组丢掉；没有名字（或名字只有空白）的套装丢掉；
  `items` 只留该组的固定分类（其余 key 丢掉），每个值按逗号切分去重；
  `picked[part]` 指向不存在 / 不属于该组的套装时置空。
- **套装 id 的规矩（手改时看这条）**：只有同时满足「单段 ASCII、1–32 字符」
  「不是保留名：`outer` / `inner` / 七个固定分类 key / `套装`」「**同一组内**没重复」才原样保留，
  否则会被现场换成一个新 id —— **条目不会丢**，只是 id 变了。不同组的 id 允许同名。
  （id 与 UI 的 `#roleEx-outfit-suit-edit-<id>` 绑定，所以不能随便占名字。）
- 解析失败的行会被跳过并计数，状态行提示一次 `已跳过 N 行无法解析的衣装数据`（写回成功后这句撤掉）。
- 手改之后请**先刷新页面**（或切一次会话）再在界面里操作，免得把磁盘上更新的内容覆盖回去。

## 群聊 / 没选角色 / 缺补丁

| 情况 | 表现 |
| --- | --- |
| **群聊** | 状态行**红字**「群聊不支持：这类文件按角色目录存放，群聊没有角色目录。」；两栏整体置灰不可点（`.roleEx-outfit-cols.is-disabled`）；**本地就判**，连请求都不发 |
| 没有选择角色 | **不当错误显示**：状态行给中性文案、**不打红字**；两栏同样置灰。真去写盘时才会弹「还没有选择角色（角色目录未知）。」 |
| **缺服务端补丁** | 状态行**红字**点明 `git apply patches/st-twitter-assets.patch` 并重启；两栏置灰；**不回退**到别的位置 |
| 补丁是旧版、白名单里没有 `outfit`（端点回 **400**） | 与「缺补丁」**同级**：状态行**红字**、两栏置灰，文案直接给可照做的指引 ——「服务端拒绝了 outfit 路径 —— 若你装的是旧版 `st-twitter-assets.patch`，请把 `src/endpoints/role-expansion-assets.js` 里的 `ALLOWED_SUBDIRS` 改成 `['twitter', 'outfit']`，然后重启酒馆主进程。」（服务端回的原始原因是 `invalid-path`，模块把它归一成页面级原因 `sub-not-allowed`：探针用的是固定合法值，只剩「`sub` 不在白名单」这条分支成立）。改完并**重启酒馆主进程**之后，**重新打开一次面板**（或刷新页面 F5）即可恢复 |
| 文件超限（413） | 红字「文件超过服务端上限（文本 16MB / 图片 8MB）。」 |
| 网络错 / 其它 HTTP 错 | 红字对应的失败文案，UI 与 Toast 共用同一份（`assetReasonText()`） |
| 网络抖动这类**非页面级**原因 | **不置灰面板**（只记一行控制台日志）；真要写盘失败时弹一条 Toast，文案同样出自 `assetReasonText()` |

不可用时**两栏整块置灰**（`.roleEx-outfit-cols.is-disabled` 带 `pointer-events: none`）—— 连 `编辑` 都点不动，
所以**根本进不了弹窗**，不会出现「打了字却写不进去」；真要写盘失败（例如网络抖动）时会弹一条错误 Toast，不静默失败。

> **恢复时机（页面级失败态）：探针每个页面只认真探一次并缓存结果。** 若你是在**页面已经打开着**的情况下
> 补的补丁 / 改的白名单 → **重启酒馆主进程后再刷新页面（F5）**，或**关掉再重新打开一次「角色扩展」面板**
> （重开这条路在失败态下会重探一次，最多每 3 秒一次）；**面板一直开着不动时不会自动恢复** ——
> 这是刻意的粒度选择（失败态不做轮询）。`group` / `no-character` 不走这条路：它们每次现算，换会话就更新。

## 已知限制

- **群聊不支持**：衣装按角色目录存放，群聊没有角色目录。
- **必须应用 `patches/st-twitter-assets.patch`，且它的子目录白名单里要有 `outfit`**（0.10.0 起默认就有）。
  已经装过旧版的人**不能**重新 `git apply` 那份补丁（文件已存在会失败），操作指引见主 README。
  改完那一行**重启酒馆主进程**之后，**重新打开一次面板**（或 F5）即可恢复 —— 探针每个页面只认真探一次
  并缓存结果，重新打开面板会在失败态下再探一次（最多每 3 秒一次）；**面板一直开着不动时不会自动恢复**。
- **预设卡片要你自己加**（扩展不碰预设文件）；加完记得在预设下拉里重新选一次该预设。
- **只有单向注入**：模型不会自己换衣服，也没有「标签回写」—— 回复里写任何东西都不会改动你的选择
  （对比「角色状态栏」：那边会解析 `<名称>值</名称>`、更新并从正文剥离）。
- **没有导入 / 导出**。
- **备选表与已选在同一个 jsonl 里**，落盘是**整文件覆盖写、无写队列**：手改后先刷新再操作；
  同一会话并发写就是「后写覆盖先写」（正常单人使用无影响）。
- **固定分类不可改名 / 不可删除**（key 是契约）；自定义分类能改名，但**不能挑部分**（永远在「其他」）。
- **分类名不能重复**（新建 / 改名时按名字整体查重，固定分类也算在内）。
- **套装只属于「外」「内」两组**：「其他」是自定义分类，既没有套装行、也不会出现在套装的下属分类里。
- **套装同组互斥**：一组最多选中一套（点另一套就是换过去）；但**与散装选择不互斥** ——
  两者会合并显示（散装在前、套装项在后、去重）并一起注入，所以「套装配一件外套」是正常用法。
- **套装名只在组内唯一**：外组与内组可以各有一个「通勤装」。
- **二级弹窗是一级弹窗之上的第二层**：编辑单个套装时一级还开着（改动保存后一级列表会就地刷新）；
  取消 / `×` 只关第二层，一级不受影响。
- **套装没有导入 / 导出，也不能整体复制到别的会话**（跟着这一份 jsonl 走）；要复用请手改 JSONL 的第 4 行。
- **套装的 `id` 由扩展生成**（用户只填名字）；手改 JSONL 时 id 必须满足「单段 ASCII 1–32 字符 + 不是保留名 + 组内不重复」，
  否则读取时会被换成新 id（条目仍在，见「存储」）。
- **世界书扫描默认关**（`outfitWIScan`）：想让衣装里的词也能触发世界书条目得自己打开，且需要 ST 侧
  `st-wi-scan-source` 补丁；补丁缺失时那一行开关**禁用并写明原因**（不静默）。
  它与「卡片是否注入主聊天」是**两个**开关，互不连坐。
- 界面文案全是硬编码简体中文，没走酒馆的 `t()`。
