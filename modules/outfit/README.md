# 衣装打扮（Outfit）

`modules/outfit/` 的**用户说明**。安装扩展、给酒馆打补丁、模块怎么启用 / 拆卸这些全局步骤见[主 README](../../README.md)；
实现细节见 [DEVELOPMENT.md](DEVELOPMENT.md)。

拆掉整个 `modules/outfit/` 目录（或在酒馆「扩展」设置面板里禁用它）= 没有衣装功能；
框架与「角色状态栏」「日记」「推特」照常工作（衣装不依赖任何其它模块，别的模块也不依赖它）。

---

## 这个模块能做什么

| 能力 | 说明 |
| --- | --- |
| 分类表 | 七个**固定分类**（外：头饰 / 上衣 / 下装 / 袜子 / 鞋子；内：内衣 / 内裤）+ 你自己建的**自定义分类**（固定落在「其他」） |
| 备选装备表 | 每个分类一个输入框，按**英文逗号**分隔填若干件 |
| 选择（可叠穿） | 点芯片切换选中，**分类内多选**；顺序恒按备选表顺序，与点击先后无关 |
| 注入主聊天 | 把「现在穿什么」按 **外 / 内 / 其他** 三行分组写进后续每一次生成，让模型的描写与对话保持一致 |
| 按会话隔离 | 一个会话一个 jsonl（备选表与已选都在这个文件里），放在该角色的聊天目录下；换角色、换存档互不干扰 |
| 手改 JSONL | 稳定三行、字段可读；读取时会自动归一化（见「存储」） |

不做的事：群聊不支持（见「群聊 / 没选角色 / 缺补丁」）；**只有单向注入** —— 模型不会自己换衣服、
也没有标签回写（这一点与「角色状态栏」相反，别混）；没有导入 / 导出；不创建 / 不修改 / 不写预设（卡片要你自己加）。

## 入口与面板结构

| 入口 | 位置 |
| --- | --- |
| 顶部工具栏的**羽毛图标** | 主面板里的「**衣装打扮**」区块 —— 排在**最上面**、**横跨整行**、**默认收起**（点标题展开；位置见主 README 的界面导览） |
| 角色卡编辑区 | `Chat Lore` 按钮右侧的羽毛按钮，打开的是同一个主面板 |

「衣装打扮」区块自上而下（正文的**直接子节点顺序是契约**）：

1. **状态行**（`#roleEx-outfit-status`）—— 正常时是 `已选 N 项 · chats/<角色目录>/_RoleExpansion/outfit/<文件名>`，
   一项都没选时是 `还没有选任何衣装项 · <同一个路径>`；有坏行时再跟一句 `· 已跳过 N 行无法解析的衣装数据`；
   不可用时换成**原因文案**（见「群聊 / 没选角色 / 缺补丁」）。
2. **左右两栏**（`.roleEx-outfit-cols`）——
   - 左：**预览**（`#roleEx-outfit-preview`，占 42% 宽）—— 按 外 / 内 / 其他 分组，一行一个分类，
     值就是当前选中的 tag（用 ` / ` 连接）；没选显示「未选」并弱化；
     分组标题是带 `.roleEx-outfit-preview-part` 的那一行。
   - 右：**编辑器**（`#roleEx-outfit-editor`）—— 三组分类，每个分类一行：
     分类名 + **备选装备表输入框** + **芯片行**；「其他」组底部是 `+ 新建分类`。
     自定义分类的行尾多两个按钮：`🖊` 改名、`🗑` 删除。
   - 窄屏（≤780px）下两栏变竖排。
   - 编辑器里每个分组的小标题用的是通用提示文字样式（元素同时带 `.roleEx-hint`），
     `roleEx-outfit-group` / `roleEx-outfit-group-head` 这两个类只作结构标记，**刻意没有单独的样式**。
3. **「注入模板」折叠块**（`#roleEx-outfit-inject-fold`，**默认收起**）—— 一个四行文本框，写注入正文的模板。

## 三大部分与分类

| 部分 | 固定分类（key 是契约的一部分） |
| --- | --- |
| **外**（`outer`） | 头饰 `hat` / 上衣 `top` / 下装 `bottom` / 袜子 `socks` / 鞋子 `shoes` |
| **内**（`inner`） | 内衣 `underwear` / 内裤 `underpants` |
| **其他**（`other`） | 你自己建的分类，key 是 `custom-<uid>` |

- 七个固定分类**不可改名、不可删除**（key 同时是注入正文与自测的契约）；JSONL 里缺了就按内置定义补齐。
- 自定义分类：点「其他」组底部的 `+ 新建分类` → 弹一个输入框 → 名字为空、或与任何已有分类重名会被拒绝；
  新建的分类**一定落在「其他」组**（不能挑部分）。
- `🗑` 删除有二次确认（`删除分类「X」？该分类的备选 tag 与已选 tag 会一起清掉。`）。

> 部分顺序（外 → 内 → 其他）**同时决定**编辑器里的分组顺序、预览里的分组顺序、以及注入正文的分行顺序。

## 备选装备表（每个分类一个输入框）

- **只按英文逗号 `,` 切分** —— 与 SillyTavern 世界书的「关键字列表」一致。
  **中文逗号 `，` 与顿号 `、` 都不是分隔符**，写进去只会变成 tag 名字的一部分。
- 每个 tag 的清洗顺序是：**按 `,` 切分 → `trim()` → 丢掉空串 → 去重保序**。
- 提交时机：输入框的 `change` 事件（离开焦点时触发；按回车会主动 `blur()` 一次，把「提交」做实）。
  内容与上次一致就什么都不做；提交成功才重画面板，失败由 store 统一弹 Toast 并把输入框拉回真实状态。
- 提交是**整表替换**：输入框里的内容就是新的备选表（落盘时写成 `tag1,tag2`，不带空格）。
- **连带清选**：新备选表里已经不存在的 tag，会同时从「已选」里清掉 —— 与读取归一化是同一套语义，
  所以「删掉一个 tag 再打回来」不会自动恢复选中。
- 芯片行由备选表生成：**点一下切换选中**（选中态是实底高亮）。点完只重画预览与状态行，不整块重画。

## 选择语义

| 问题 | 答案 |
| --- | --- |
| 一个分类能选几个？ | **不限个，分类内多选** —— 想叠穿就都点上 |
| 顺序按什么？ | **恒按备选表的顺序**，与点击先后无关（JSONL 里也只存「选了哪些」，不存顺序） |
| 怎么取消？ | 再点一次该芯片 |
| 注入时怎么显示？ | 同一个分类里的多个 tag 用 ` / ` 连接（见下节） |

## 注入主聊天

### 预设里必须由你自己加一张 marker 卡片

衣装注入走酒馆原生的**有序提示词**机制：预设里放一张 `marker: true` 卡片（`identifier` = `roleExpansionOutfit`），
正文由扩展在每次生成时**现算**提供。卡片片段（写进预设 JSON）：

```jsonc
// 1) prompts 数组里追加一条
{
    "identifier": "roleExpansionOutfit",
    "name": "衣装（角色扩展）",
    "system_prompt": true,
    "marker": true
}
```

```jsonc
// 2) prompt_order 里【每个 character_id 块】都要加一条
{ "identifier": "roleExpansionOutfit", "enabled": true }
```

- 卡片**在不在、落在哪个 `prompt_order` 块、开还是关**，全都在酒馆预设 UI（「AI Response Configuration」）里管；
  扩展**不创建、不修改、不移动**卡片，也不写预设文件。没加卡片时，面板的诊断文案会把上面这段 JSON 直接贴给你。
- **卡片上的开关是「是否注入主聊天」的唯一开关**：关掉 → 运行时正文源返回空串 → 不注入；扩展**绝不**擅自改回来。
- 打开预设面板的快捷入口：「扩展」设置面板 →「衣装卡片 · `roleExpansionOutfit`」那一块里的 `打开预设面板` 按钮。
- **扩展设置面板**里属于本模块的那一块叫「衣装卡片 · `roleExpansionOutfit`」，给的是**诊断**（没有任何可改项）：
  当前预设名、卡片形态（`marker=true`）、所在 `prompt_order` 块与前后邻居、`enabled`，以及权限 / 补丁检测的结论。

### 注入正文长什么样

模板在面板的「注入模板」折叠块里（设置键 `outfitInjectPrompt`，默认两行）：

```text
[以下是 {{char}} 当前的衣装打扮，请在描写与对话中保持一致]
{{outfitList}}
```

- `{{outfitList}}` 是**扩展填的**（store 拼好的分组清单）；其余 `{{...}}` 交给酒馆的宏替换（`{{char}}` / `{{user}}`…）。
- 分组清单：**每部分一行**，行内是 `分类名=tag1 / tag2`，同一行里多个分类用 `；` 连接；**空的部分整行不出现**。
  例（外：头饰与袜子有选，上衣 / 下装 / 鞋子没选；内、其他都没选）：

  ```text
  外：头饰=贝雷帽 / 发带；袜子=黑色过膝袜
  ```

- **一个 tag 都没选 → 整条不注入**（不是「注入一行空标题」）。
- 模板框的改动是 400ms 防抖后落设置，立刻生效（不需要刷新页面）。

### 三道正文闸

正文源每次被调用时按顺序判三件事，任一不过就返回空串（= 不注入）：

| # | 条件 | 结果 |
| :---: | --- | --- |
| ① | 卡片**没插进任何** `prompt_order` 块 | 空串（此时连开关都没有，诊断显示 `位置：没有插进任何 prompt_order 块 —— 卡片不会参与生成`） |
| ② | 卡片 `enabled === false` | 空串（诊断显示 `🔴 已停用（不注入）`） |
| ③ | **一个衣装项都没选** | 空串 |

## 存储：落点与手改 JSONL

```text
<user>/chats/<角色目录>/_RoleExpansion/outfit/
└── RoleExpansion_outfit_c_<角色hash8>_j_<会话hash8>.jsonl   三行：会话头 + 分类表 + 已选 tag
例：chats/樱井 奈奈/_RoleExpansion/outfit/RoleExpansion_outfit_c_1a2b3c4d_j_5e6f7a8b.jsonl
```

- **为什么跟着角色走**：落点就是角色的聊天目录，角色改名 / 换头像时酒馆会把整个目录搬过去，衣装跟着搬；
  删除角色并勾选「删除聊天」时连根删除。
- **换会话换文件**（文件名里的两个 hash 分别来自角色目录名与会话名），所以同一个角色的两个存档各穿各的。
- **酒馆看不见它**：酒馆列出聊天文件的所有代码路径都只扫 `chats/<角色>/` **本级**且要求是文件，
  所以子目录里的 jsonl 不会被列出来、也不会被当成聊天加载。
- **文件名必须是单段 ASCII**（沿用酒馆的文件名校验）：中文 / 空格 / 括号一律不进文件名，
  可读的角色目录名与会话名记录在**第一行的会话头**里。
- 读写走服务端补丁提供的 `POST /api/role-expansion/asset/{get,save,delete}`（`sub` = `outfit`，
  服务端子目录白名单里必须有它，见主 README 的「打补丁」）。缺补丁时明确报错（`patch-missing`），**不回退**到别的位置。

### 三行结构

```text
第 1 行  {"__roleExpansion":"outfit-session","version":1,"chatId":…,"charDir":…,"chatFile":…,"savedAt":…}
第 2 行  {"__roleExpansion":"outfit-catalog","categories":[{"key":…,"part":…,"name":…,"custom":…,"tags":[…]}],"updatedAt":…}
第 3 行  {"__roleExpansion":"outfit-selection","picked":{"hat":["贝雷帽","发带"]},"updatedAt":…}
```

```json
{"__roleExpansion":"outfit-catalog","categories":[{"key":"hat","part":"outer","name":"头饰","custom":false,"tags":["贝雷帽","发带"]},{"key":"custom-1a2b3c","part":"other","name":"配饰","custom":true,"tags":["耳坠"]}],"updatedAt":0}
```

- **第 2 行是备选表**（面板右侧编辑器的输入框）、**第 3 行是已选**（预览与注入正文只看这一份）。
  两者都在**同一个**文件里 —— 手改可行，但落盘是**整文件覆盖写、没有写队列**。
- 写回时永远是「会话头 + 分类表 + 选择表」**稳定的三行**，字段与顺序固定。
- **读不动就丢掉**：固定分类按内置定义补齐；`part` 不在已知部分里的自定义分类丢掉；
  既不是内置分类、又不带 `custom-` 前缀的 key 丢掉；`picked` 里不在分类表里的 key、
  以及不在该分类备选表里的 tag 都丢掉。
- 解析失败的行会被跳过并计数，状态行提示一次 `已跳过 N 行无法解析的衣装数据`（写回成功后这句撤掉）。
- 手改之后请**先刷新页面**（或切一次会话）再在界面里操作，免得把磁盘上更新的内容覆盖回去。

## 群聊 / 没选角色 / 缺补丁

| 情况 | 表现 |
| --- | --- |
| **群聊** | 状态行**红字**「群聊不支持：这类文件按角色目录存放，群聊没有角色目录。」；两栏整体置灰不可点（`.roleEx-outfit-cols.is-disabled`）；**本地就判**，连请求都不发 |
| 没有选择角色 | **不当错误显示**：状态行给中性文案、**不打红字**；两栏同样置灰。真去写盘时才会弹「还没有选择角色（角色目录未知）。」 |
| **缺服务端补丁** | 状态行**红字**点明 `git apply patches/st-twitter-assets.patch` 并重启；两栏置灰；**不回退**到别的位置 |
| 补丁是旧版、白名单里没有 `outfit`（端点回 **400**） | 与「缺补丁」**同级**：状态行**红字**、两栏置灰，文案直接给可照做的指引 ——「服务端拒绝了 outfit 路径 —— 若你装的是旧版 `st-twitter-assets.patch`，请把 `src/endpoints/role-expansion-assets.js` 里的 `ALLOWED_SUBDIRS` 改成 `['twitter', 'outfit']`，然后重启酒馆主进程。」（服务端回的原始原因是 `invalid-path`，模块把它归一成页面级原因 `sub-not-allowed`：探针用的是固定合法值，只剩「`sub` 不在白名单」这条分支成立）。改完并**重启酒馆主进程**之后，**重新打开一次面板**（或刷新页面 F5）即可恢复 |
| 文件超限（413） | 红字「文件超过服务端上限（文本 16MB / 图片 8MB）。」 |
| 网络错 / 其它 HTTP 错 | 红字对应的失败文案，UI 与 Toast 共用同一份（`assetReasonText()`） |
| 网络抖动这类**非页面级**原因 | **不置灰面板**（只记一行控制台日志）；真要写盘失败时弹一条 Toast，文案同样出自 `assetReasonText()` |

不可用时输入框照旧能打字，只是写不进去 —— 会弹一条错误 Toast，不静默失败。

> **恢复时机（页面级失败态）：探针每个页面只认真探一次并缓存结果。** 若你是在**页面已经打开着**的情况下
> 补的补丁 / 改的白名单 → **重启酒馆主进程后再刷新页面（F5）**，或**关掉再重新打开一次「角色扩展」面板**
> （重开这条路在失败态下会重探一次，最多每 3 秒一次）；**面板一直开着不动时不会自动恢复** ——
> 这是刻意的粒度选择（失败态不做轮询）。`group` / `no-character` 不走这条路：它们每次现算，换会话就更新。

## 已知限制

- **群聊不支持**：衣装按角色目录存放，群聊没有角色目录。
- **必须应用 `patches/st-twitter-assets.patch`，且它的子目录白名单里要有 `outfit`**（0.10.0 起默认就有）。
  已经装过旧版的人**不能**重新 `git apply` 那份补丁（文件已存在会失败），操作指引见主 README。
  改完那一行**重启酒馆主进程**之后，**重新打开一次面板**（或 F5）即可恢复 —— 探针每个页面只认真探一次
  并缓存结果，重新打开面板会在失败态下再探一次（最多每 3 秒一次）；**面板一直开着不动时不会自动恢复**。
- **预设卡片要你自己加**（扩展不碰预设文件）；加完记得在预设下拉里重新选一次该预设。
- **只有单向注入**：模型不会自己换衣服，也没有「标签回写」—— 回复里写任何东西都不会改动你的选择
  （对比「角色状态栏」：那边会解析 `<名称>值</名称>`、更新并从正文剥离）。
- **没有导入 / 导出**。
- **备选表与已选在同一个 jsonl 里**，落盘是**整文件覆盖写、无写队列**：手改后先刷新再操作；
  同一会话并发写就是「后写覆盖先写」（正常单人使用无影响）。
- **固定分类不可改名 / 不可删除**（key 是契约）；自定义分类能改名，但**不能挑部分**（永远在「其他」）。
- **分类名不能重复**（新建 / 改名时按名字整体查重，固定分类也算在内）。
- 界面文案全是硬编码简体中文，没走酒馆的 `t()`。
