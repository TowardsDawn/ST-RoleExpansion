# 日记（Journal）

`modules/journal/` 的**用户说明**。安装扩展、给酒馆打补丁、往预设里写卡片这些全局步骤见[主 README](../../README.md)；
实现细节见 [DEVELOPMENT.md](DEVELOPMENT.md)。

拆掉整个 `modules/journal/` 目录（或在酒馆「扩展」设置面板里禁用它）= 没有日记功能，
框架与「角色状态栏」照常工作。

---

## 这个模块能做什么

| 能力 | 说明 |
| --- | --- |
| 生成日记 | 勾选参考楼层 → 用当前配置的 API，以角色第一人称写一篇，写完直接落盘；**不往主聊天里写消息** |
| 让角色「记得」 | 在日记列表里勾选几篇 → 打开预设里那张 `roleExpansionJournal` 卡片的开关 → 之后每次生成都带上它们 |
| 写新日记时参考旧日记 | 勾选几篇 + 打开「插入日记系统」→ 它们被拼进**写新日记的提示词**（`{{journalRefs}}`），而不是注入主聊天 |
| 标题 | 留空由模型随正文生成（`<title>` / `标题：` / 首行 `# 标题` / `【标题】` 四种形式都能解析），也可以自己填、之后随时改 |
| 管理 | 编辑（标题 + 正文）、删除（单篇 / 所选）、导出（全部 / 所选 / 单篇）、导入（追加或覆盖）、单篇「仅此篇」 |
| 按会话隔离 | 一个会话一个 `.jsonl` 文件，放在该角色的聊天目录下；换角色、换存档互不干扰 |

不做的事：群聊不支持（见「已知限制」）、日记不写回角色卡、扩展不创建 / 不修改 / 不移动你的预设卡片。

## 入口

| 入口 | 位置 |
| --- | --- |
| 顶部工具栏的**羽毛图标** | 主面板里的「日记」区块（与「角色状态栏」并列），图标位置见主 README 的界面导览 |
| 角色卡编辑区 | `Chat Lore` 按钮右侧的羽毛按钮，打开同一个主面板 |
| 酒馆「扩展」设置面板 | 「日记卡片 · `roleExpansionJournal`」区块：卡片完整诊断 + 「打开预设面板」按钮 |

主面板里的「日记」区块自上而下：

1. **提示词注入** —— 一行状态：`注入状态：🟢 已启用（注入中）` / `🔴 已停用（不注入）`，
   或 ⚠️ 各类不可用提示（读不到提示词管理器 / 预设里没有这张卡片 …）。**完整诊断在「扩展」设置面板**。
2. **新日记** —— 标题输入框 + `生成日记` 按钮 + 「隔离生成（推荐）」开关
   + 「角色设定（隔离通道）」折叠块（**默认收起**）+ 「参考聊天楼层」折叠块（**默认展开**）。
3. **日记列表** —— 「插入日记系统」复选框 → 计数与落点行 → 存储说明 → 日记条目 → 操作按钮行。
4. **日记主提示词（可自由修改）** —— 默认收起，见下文。

## 生成日记的完整流程

### 1. 勾选参考楼层

「参考聊天楼层」里列出当前会话所有**有正文**的楼层（`mes` 为空的消息不出现），每行显示 `#索引`、说话人、正文预览。

- 逐条勾选
- 快捷按钮：`最近 10 楼` / `全选` / `清空` / `刷新楼层`
- **区间选择**：在「第 `N` ~ `M` 楼」里填数字后点「选中区间」。编号与列表里的 `#号` 一致，**0 起、两端都含**；
  反向填写（`M < N`）自动交换；区间里一个可用楼层都没有时只弹提示，**不改动**当前勾选
- 换会话时勾选会被清空；面板打开时会重新枚举当前会话的楼层（面板关着时楼层列表要等下一次打开才刷新）

### 2.（可选）把已勾选的日记当参考：「插入日记系统」

- 「插入日记系统」是「日记列表」折叠块的**第一行**
- 它决定上面那些日记勾选**拿去干什么**：打开 = 拼进写新日记提示词的 `{{journalRefs}}`；
  关闭 = 不拼（提示词里会写明「未开启」）
- 它**不是**「是否注入主聊天」的开关 —— 那件事由预设卡片的开关决定，见下一节

### 3.（可选）填标题

标题输入框留空 = 由模型随正文生成；填了 = **覆盖**模型给的标题（生成成功后输入框会被清空）。

### 4. 点「生成日记」

- 日记无处可写时（群聊 / 缺服务端补丁 / 没选角色）**直接拒绝**，不会白跑一次生成
- 上一次生成还没结束 → 提示「正在生成中，请稍候…」
- 楼层与参考日记都没勾 → 弹一次确认「尚未勾选任何聊天楼层与参考日记，仍然生成吗？」
- 生成期间按钮文案变为「生成中…」；**这次请求不会把旧日记注入回去**（见「注入机制」）
- 模型返回空内容 → 提示「模型返回了空内容。」，不写条目
- 成功后立即写入当前会话的 jsonl，并提示「已写入日记：<标题>」

### 5. 写好后编辑 / 删除

- 条目上的 `编辑` 打开弹窗改标题 + 正文，保存即落盘（同时更新 `updatedAt`）
- `删除`（单篇）或勾选后「删除所选」，二次确认「确定删除 N 篇日记？此操作不可撤销。」
- 同一条操作行里还有 `仅此篇` / `导出`（单篇）

### 「仅此篇」的语义

点某篇的「仅此篇」= 把日记勾选集合**替换成只有这一篇**，然后立即刷新列表与注入状态。
它不改这篇的内容，也不碰预设 —— 适合「这次只让它记得这一件事」。

## 预设里的 marker 卡片（只读契约）

日记注入走酒馆原生的**有序提示词**机制：预设里放一张 `marker: true` 卡片，正文由扩展在每次生成时**现算**提供。
卡片片段（写进预设 JSON，见主 README 的「写预设卡片」）：

```jsonc
// 1) prompts 数组里追加一条
{
    "identifier": "roleExpansionJournal",
    "name": "日记（角色扩展）",
    "system_prompt": true,
    "marker": true
}
```

```jsonc
// 2) prompt_order 里【每个 character_id 块】都要加一条，位置建议紧跟 worldInfoAfter
{ "identifier": "roleExpansionJournal", "enabled": true }
```

- `marker: true` = 「正文不来自预设、由运行时提供」，所以**不要**给这条卡片写 `content`
- **卡片上的开关是「是否注入主聊天」的唯一开关**：关掉 → 运行时正文源返回空串 → 不注入；
  扩展**绝不**擅自改回来
- 位置 / 名字 / 启停都在酒馆预设 UI 里管（`examples/preset.example.json` 已内置这张卡片，可直接导入对照）；
  改完预设文件后要在预设下拉里**重新选一次**该预设
- 卡片在不在、落在哪个 `prompt_order` 块、前后邻居是谁，用「扩展」设置面板的日记卡片区块或
  `roleExpansion.diagnoseJournalCard()` 都能看清

扩展对预设**只读**：

| 状态 | 扩展的行为 |
| --- | --- |
| `prompts` 里没有该 identifier | **什么都不做**，诊断文案把该写的 JSON 片段贴出来 |
| `prompt_order` 里没有该条目 | 视为未启用，状态显示 `🔴 已停用（不注入）` |
| 卡片已存在 | 只**读**形态与 `enabled`，不增删字段、不改位置、不改开关 |
| 任何时候 | **不调用** `/api/presets/save`，不写预设文件 |

### 「插入日记系统」≠「注入主聊天」

| | 开关在哪 | 管什么 |
| --- | --- | --- |
| 注入主聊天 | 预设里那张卡片的**开关** | 勾选的日记会不会出现在后续每一次主聊天生成里 |
| 插入日记系统 | 面板「日记列表」第一行的复选框 | 勾选的日记会不会被拼进**写新日记**的提示词（`{{journalRefs}}`） |

两者互相独立：可以只注入主聊天（关掉「插入日记系统」），也可以只当参考（关掉卡片开关）。

## 隔离生成 vs 安静生成

「新日记」区有一个**默认开启**的开关「隔离生成（推荐）」：

| | 隔离生成（默认） | 安静生成（回退） |
| --- | --- | --- |
| ST 侧接口 | `generateRaw({ prompt, systemPrompt? })` | `generateQuietPrompt({ quietPrompt, quietToLoud: false, skipWIAN: true })` |
| 请求里有什么 | 日记提示词（一条 `user` 消息）；角色设定有内容时再加一条 `system` | 完整 system 提示词组 + **整条主聊天记录** + 末尾的写日记指令 |
| 角色卡 | 由扩展按三个开关自己拼（见下一节） | 由预设里的 `charDescription` / `personaDescription` / `scenario` 卡片提供，扩展**不**再拼 |
| 何时用 | 默认；换模型也不会被主聊天语境带跑 | 关掉「隔离生成」、或该接口缺失时的兜底 |

区别的本质：`generateQuietPrompt` 是**后台生成**（结果不进聊天记录），不是**上下文隔离** —— 它会把整条主聊天记录一并送给模型。
对倾向延续叙事的模型，就可能变成「接着最新剧情往下写」；隔离通道从根上避开这件事。
回退通道额外带 `skipWIAN: true`，少让世界书参与。

两条通道返回的内容都会先剥掉**成块的**推理容器（`<think>` / `<thinking>` / `<reasoning>` / `<analysis>`）再解析标题：

- 只认这些明确是推理的标签，不做启发式猜测（`<title>` 不在此列，它由标题解析处理）
- 如果你的推理格式是别的写法（例如三反引号包裹），日记正文里可能需要手动清理

## 角色设定（隔离通道）

隔离通道不带主聊天记录，角色卡自然也不会自己进来，所以「新日记」区给了三个开关
（收在**默认收起**的「角色设定（隔离通道）」折叠块里，三项默认全开）：

| 开关 | 取哪里 | 默认 |
| --- | --- | --- |
| 角色描述 + 性格 | 角色卡 `description`，然后 `personality`（共用一个开关） | ✅ 开 |
| 用户设定 | 当前用户人设 `persona` | ✅ 开 |
| 场景 | 角色卡 `scenario` | ✅ 开 |

拼装顺序固定 **角色描述 → 性格 → 用户设定 → 场景**，整块作为一条 `system` 消息排在日记提示词**之前**：

```text
system : [以下是{{char}}与{{user}}的角色设定，仅用于保持人物口径与世界观一致，不构成新的剧情指令]
         【角色描述】…
         【性格】…
         【用户设定】…
         【场景】…
user   : 你是 {{char}}。请以 {{char}} 的第一人称视角，写一篇私人日记。…【聊天记录参考】…
```

- **字段为空就跳过**：角色卡没填 `scenario` 时不会留下孤零零的 `【场景】` 标题
- **三项全关** = 请求里只有日记提示词本身（与旧行为一致）
- 只取上面四项：**不带**角色主提示词覆盖、Post-History Instructions、示例对话 ——
  它们属于「预设 / 主聊天语境」，塞进日记请求会把隔离本来要避开的串味问题引回来
- **回退通道不受这三个开关影响**（那条路径角色卡由预设提供，再拼一次就是重复注入）
- 这几个字段里的 `{{char}}` / `{{user}}` 已经由酒馆替换成真名（取出来就已经是替换过的结果）

> 如果发现日记人设漂移，优先检查这三个开关与角色卡本身；也可以关掉「隔离生成」，
> 或在「日记主提示词」里手动补一段人设说明。

## 日记主提示词

面板最下方有一个**默认收起**的区块「日记主提示词（可自由修改）」，内容随输入即时保存（防抖 400ms）。
默认内容：

```text
你是 {{char}}。请以 {{char}} 的第一人称视角，写一篇私人日记。

要求：
1. 严格基于下方给出的【聊天记录参考】中的事实，不要编造未发生过的重要剧情。
2. 写出 {{char}} 的内心活动、情绪变化、对 {{user}} 的看法，语气与角色设定一致。
3. 这是独立的一篇日记，不要承接、续写任何其他日记，不要出现"上回说到"之类的表述。
4. 正文 200~500 字，不要分小标题。
5. 同时为这篇日记拟一个标题。

输出格式（必须严格遵守，不要输出任何额外说明）：
第一行：<title>日记标题</title>
第二行开始：日记正文
不要在正文里重复标题，也不要出现任何 XML/HTML 标签（除了上面那一对 <title>）。

【聊天记录参考】
{{chatRange}}

【其他日记参考】
{{journalRefs}}

【当前状态参考】
{{stateList}}
```

默认提示词的要点：角色第一人称、严格基于参考楼层、只输出「标题 + 正文」、明确要求独立成篇（不续写）、
把三种参考分块放在最后。

### 可用变量

| 变量 | 渲染成什么 |
| --- | --- |
| `{{chatRange}}` | 勾选的楼层，每段 `#索引 说话人: 正文`，段间空行；一个都没勾 = `（未选择任何聊天楼层）` |
| `{{journalRefs}}` | 勾选的参考日记（每篇 `【标题】\n正文`，用 `---` 分隔）；「插入日记系统」关闭 = `（未开启「插入日记系统」开关）`，没勾选 = `（未勾选任何参考日记）` |
| `{{stateList}}` | 当前状态列表（由「角色状态栏」模块提供）；状态模块被拆掉 / 没有状态时 = `（暂无状态）`，关掉状态联动时 = `（未开启状态联动）` |
| `{{char}}` / `{{user}}` 等 | 变量替换完成后，整段交给酒馆宏系统替换 |

> 「状态并入日记生成提示」的开关在**角色状态栏**区块里，不在日记区块。
> 这个区块**没有**单项「恢复默认」按钮：要还原主提示词，用酒馆「扩展」设置面板里的「恢复默认设置」
> （按你「存为默认设置」保存的基准整体还原）。
> 另外几个没有面板 UI 的日记设置键（注入头尾文案、是否带标题、参考日记的说明行等）只能在控制台改
> `roleExpansion.settings`，改完可以用「存为默认设置」把它们存进基准。

## 存储

```text
<ST>/data/<用户名>/chats/<角色目录>/_RoleExpansion/journals/RoleExpansion_journal_c_<角色hash8>_j_<会话hash8>.jsonl
例：chats/樱井 奈奈/_RoleExpansion/journals/RoleExpansion_journal_c_91aa9dee_j_67d659dc.jsonl
```

- 面板日记列表上方那行会显示当前会话的落点路径（`chats/<角色>/_RoleExpansion/journals/<文件名>`）；
  不可用时会换成原因文案
- **为什么跟着角色走**：落点就是角色的聊天目录，所以角色**改名 / 换头像**时酒馆会把整个目录搬过去，日记跟着搬；
  删除角色并勾选「删除聊天」时连根删除 —— 与「角色的私人物品」语义一致
- **酒馆看不见它**：酒馆列出聊天文件的所有代码路径都只扫 `chats/<角色>/` **本级**、且要求是文件，
  所以这个子目录里的 jsonl 不会被列出来，也不会被当成聊天加载
- **文件名必须是单段 ASCII**（沿用酒馆的文件名校验 `^[a-zA-Z0-9_\-.]+$`），所以中文 / 空格 / 括号一律不进文件名：
  角色与会话只进 hash（各 8 位十六进制），**可读的角色目录名与会话名记录在文件首行的会话头里**
- **群聊不支持**：群聊的聊天文件在 `group chats/`，没有「角色目录」这个概念；面板红字提示，「生成日记」直接拒绝
- 读写走服务端补丁提供的 `POST /api/role-expansion/journal/{get,save}`（补丁见主 README）。
  缺补丁时明确报错（`patch-missing`），**不回退**到别的位置 —— 也不再有「写进 `user/files/`」这种老行为

### 文件结构

- **第 1 行 = 会话头**：`__roleExpansion: "session"`、`version`、`chatId`、`charDir`、`chatFile`、`charSlug`、
  `savedAt`、`count`
- **之后每行 = 一篇日记**：

```json
{"__roleExpansion":"journal","id":"...","title":"...","content":"...","createdAt":0,"updatedAt":0,
 "charName":"...","userName":"...","chatId":"...","sourceMessageIds":[1,2,3],"sourceJournalIds":[],
 "stateSnapshot":[],"meta":{}}
```

- 正文里的换行以字面 `\n` 转义保存，保证「一行一篇」不被破坏
- 每次落盘都是**整文件覆盖写**（会话头 + 全部条目），同一会话并发写不排队
- 读取时非法行会被跳过并计数，会提示一次「日记文件有 N 行无法解析，已跳过。」
- 首行的会话头只是**记录**（`charDir` / `chatFile` 可读；`chatFile` 字段同时也是「这篇日记属于哪个会话」的痕迹）。
  **导入时不校验来源会话**，文件可以随便搬、跨会话导

### 从旧版本 `user/files/` 手动迁移

文件名不变，照搬即可（文件名里的 hash 只与「角色名 + 会话名」有关，与所在目录无关）：

```bash
mkdir -p "<ST>/data/<用户名>/chats/<角色目录>/_RoleExpansion/journals"
mv "<ST>/data/<用户名>/user/files/RoleExpansion_journal_c_"*"_j_"*".jsonl" \
   "<ST>/data/<用户名>/chats/<角色目录>/_RoleExpansion/journals/"
```

搬错角色目录只会让那个角色的日记读不到（文件还在，不会丢）；命令里是单角色示例，多角色请逐个角色搬。

## 导入 / 导出 / 编辑 / 删除

| 操作 | 行为 |
| --- | --- |
| 导出 | 当前会话全部日记 → 一个 `.jsonl`（首行会话头 + 每篇一行）；文件名是纯 ASCII 的 `<角色slug>__<会话slug>__<时间戳>.jsonl` |
| 导出所选 | 只导出勾选的那些（同样带会话头） |
| 单篇 `导出` | 只导出这一篇，文件名用标题（非法字符会替换掉），**不写会话头** |
| 导入 | 选 `.jsonl` / `.json` / `.txt`；弹窗「确定 = 追加到当前会话；取消 = 覆盖当前会话的日记」；与现有日记 id 冲突的会自动换新 id |
| 编辑 | 标题 + 正文弹窗，保存即落盘 |
| 删除 | 单篇 `删除` 或勾选后「删除所选」，二次确认后落盘 |

> 读失败 / 写失败**不会**伪装成「本会话还没有日记」：列表与计数行直接显示原因（群聊 / 缺补丁 / 路径被拒 / 超限 / 网络错），
> 并且**只在原因变化时**弹一次提示，不会反复弹。

## 已知限制

- **群聊不写日记**：判定为不可用（原因 `group`），「生成日记」直接拒绝
- **没有选择角色时不可用**：拿不到头像就推不出角色目录（原因 `no-character`）。这一条**不当错误显示**：
  存储说明换成一句中性的「选一个角色后才有落点。」、空列表照旧说「本会话还没有日记。」，也不弹 Toast
- **需要服务端补丁**：没打 `patches/st-journal-store.patch` 时日记读写直接失败（原因 `patch-missing`），且不回退到别的位置
- **预设卡片要你手动维护**：扩展不创建 / 不修改 / 不移动卡片，位置与启停都在预设 UI 里
- **改名时若「新目录已存在」，日记会留在旧目录**：酒馆迁移聊天目录的条件是「旧目录存在 **且** 新目录不存在」，
  这种情况整段迁移被静默跳过；文件不会丢，但新名字下读不到，需要在 `chats/` 里手动搬一次
- **同一会话并发写不排队**：落盘是整文件覆盖写，正常单人使用无影响
- **隔离通道不带世界书**（`generateRaw` 不经过酒馆的 promptManager 管线）
- **只取角色卡的四个字段**（描述 / 性格 / 人设 / 场景），不带角色主提示词覆盖、Post-History Instructions、示例对话
- **推理块剥离只认成块标签**（`<think>` / `<thinking>` / `<reasoning>` / `<analysis>`），别的写法要手动清理
- **`{{stateList}}` 由「角色状态栏」模块提供**：模块被拆掉/禁用时恒为 `（暂无状态）`
- **面板里没有「插入主聊天」开关**：这是刻意的，唯一开关是预设卡片上那个
- 标题最长取 **60** 个字符；模型没给标题时兜底成本地时间 `M月D日 HH:MM`
- 界面文案全是硬编码简体中文，没走酒馆的 `t()`
